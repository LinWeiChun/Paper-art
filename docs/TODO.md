# 開發待辦

整理日期：2026-10-07。流程與案例詳見 [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md)。

P0：先處理核心流程與發布阻礙；P1：接續功能、安全及資料維運；P2：不影響核心操作的改善。
各階段表示建議順序；若確認安全或資料風險，應提高優先級。
勾選完成前需留下版本、驗證環境與結果；既有完成紀錄另列，避免誤認為本輪已驗證。

完成條件：對應案例通過，無未處理的核心流程阻斷；無法重現的問題保留待追蹤，不標示已修復。

完成條件：各條件獨立及組合案例通過，無結果與錯誤狀態可辨識。
非核心畫面的視覺調整列為 P2，個別建立項目後安排。

## 第四階段：安全與資料維運（P1）

相依：先查核既有設定與資料保留需求；有風險的項目可提前處理。

- [ ] 查核 Cloudflare Access 保護對象及登入 Rate Limit，補足缺口並保存驗證結果。
- [ ] 查核 GitHub main ruleset 的 PR、審查、必要 CI、禁止直接及強制推送規則。
- [ ] 規劃 Flyway：確認現有 schema、baseline 與版本變更，在隔離資料庫驗證後才安排導入。
- [ ] 定義 MySQL 備份頻率、保留期、可接受資料損失與復原時間，完成隔離還原演練。
- [ ] 定義回收站期限、還原行為與權限，確認資料庫及 R2 關聯。
- [ ] 定義 R2 生命週期與孤立檔案清理規則，先產生待處理清單再評估執行。
- [ ] 擴充多 instance 前，完成登入限制共用計數設計與驗證；目前不以此要求新增基礎設施。

完成條件：安全設定有查核證據，資料變更與還原流程經驗證，保留及刪除規則已確認。
